# RAG Pipeline for a Knowledge Base

A complete, beginner-friendly Retrieval-Augmented Generation (RAG) system built with Python, LangChain, sentence-transformers, FAISS, and Ollama.  Everything runs **locally** — no API keys, no cloud services.

---

## Project Overview

This project demonstrates a full RAG pipeline that:

1. Loads a knowledge base of plain-text documents about AI topics
2. Cleans and splits them into overlapping chunks
3. Generates semantic embeddings for each chunk
4. Stores the embeddings in a FAISS vector index
5. Retrieves the most relevant chunks for any user query
6. Sends only the retrieved context to a local Ollama LLM
7. Generates a grounded, citation-aware answer
8. Refuses to invent information not supported by the knowledge base
9. Provides a quantitative evaluation with retrieval and generation metrics

## Architecture

```
Knowledge Base (data/*.txt)
         ↓
   ingest.py
   ┌─────────────────────────────┐
   │  Load documents             │
   │  Clean whitespace           │
   │  Split into chunks          │
   │  Attach metadata            │
   └───────────┬─────────────────┘
               ↓ vectorstore/chunks.pkl
   index.py
   ┌─────────────────────────────┐
   │  Load chunks                │
   │  Generate embeddings        │
   │  (all-MiniLM-L6-v2)         │
   │  Build FAISS IndexFlatL2    │
   └───────────┬─────────────────┘
               ↓ vectorstore/index.faiss + metadata.pkl
               
         User Query
               ↓
   retrieve_generate.py
   ┌─────────────────────────────┐
   │  Embed query                │
   │  Search FAISS (top-k=4)     │
   │  Build context + sources    │
   │  Fill RAG prompt template   │
   │  Call Ollama / llama3.2     │
   └───────────┬─────────────────┘
               ↓
   Grounded Answer + Citations + Confidence
```

## Installation

### 1. Create a virtual environment

```bash
python -m venv .venv
```

**Activate on Windows:**
```bash
.venv\Scripts\activate
```

**Activate on macOS / Linux:**
```bash
source .venv/bin/activate
```

### 2. Install Python dependencies

```bash
pip install -r requirements.txt
```

This installs LangChain, sentence-transformers, FAISS, and the Ollama integration.  The first install may take a few minutes.

---

## Ollama Setup

Ollama runs large language models locally on your machine — no internet connection or API key required after the initial model download.

### 1. Install Ollama

Download and install from: https://ollama.com

### 2. Pull the language model

```bash
ollama pull llama3.2
```

This downloads the `llama3.2` model (~2 GB).

### 3. Start the Ollama server

```bash
ollama serve
```

Leave this terminal window open.  The server must be running when you use `retrieve_generate.py` or `evaluate.py`.

> **Note:** On macOS, Ollama may start automatically after installation and does not need a separate `ollama serve` command.

## Running the Pipeline

Run these commands in order, from the project root directory.

### Step 1 — Ingest documents

```bash
python ingest.py
```

Expected output:
```
Documents loaded: 10
  - 'artificial_intelligence.txt'  Introduction to Artificial Intelligence
  ...
Total chunks created: ~90
Chunks saved to: vectorstore/chunks.pkl
```

### Step 2 — Build the vector index

```bash
python index.py
```

Expected output:
```
Loaded 90 chunks
Encoding 90 chunks ...
FAISS index built: 90 vectors, dimension 384
Saved FAISS index → vectorstore/index.faiss
Saved metadata   → vectorstore/metadata.pkl
```

### Step 3 — Ask questions

```bash
python retrieve_generate.py
```

Then type your question:
```
Ask a question: What is Retrieval-Augmented Generation?
```

Type `exit` or `quit` to leave.

### Step 4 — Run evaluation

```bash
python evaluate.py
```

This runs all 11 evaluation questions and writes `evaluation/evaluation_report.md`.

## Example Query and Answer

**Question:** What is RAG and how does it reduce hallucinations?

**System output:**
```
Retrieved Context:

  [Source: rag.txt | Chunk: 0]
  Retrieval-Augmented Generation (RAG) is an AI architecture that enhances
  large language models by combining them with a retrieval system ...

  [Source: large_language_models.txt | Chunk: 3]
  LLMs are prone to hallucination — generating plausible-sounding but
  factually incorrect information ...

========================================
ANSWER
========================================
RAG reduces hallucinations by providing relevant factual context from an
external knowledge base before the language model generates a response [1].
Instead of relying solely on the model's parametric (stored) knowledge,
which can be imprecise or outdated, the model is grounded in retrieved
text [1]. The RAG prompt explicitly instructs the model to use only the
provided context and to refuse to answer when the context is insufficient [1].

While RAG significantly reduces hallucinations, it does not eliminate them.
If the relevant document is not in the knowledge base, or if retrieval fails
to find it, the model may still generate incorrect information [2].

Sources:
[1] rag.txt
[2] large_language_models.txt

Confidence: High
========================================
```

## Limitations

- **Knowledge base is static.** The index must be rebuilt when documents change.
- **Retrieval quality limits answer quality.** If the relevant chunk is not retrieved, the model cannot answer correctly.
- **Hallucinations are reduced, not eliminated.** The model may blend retrieved context with its parametric knowledge.
- **Chunk boundaries.** Important context may be split across two chunks, causing incomplete retrieval.
- **Single modality.** This pipeline handles text only; images, tables, and PDFs require additional processing.
- **Local hardware.** LLM inference with Ollama is slower on CPU-only machines.
- **Evaluation metrics are simplified.** Retrieval hit rate and citation rate are proxies, not rigorous measures of answer quality.
